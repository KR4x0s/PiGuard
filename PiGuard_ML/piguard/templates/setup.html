01 · WIRED UPLINK

Jio LAN → Pi Ethernet

Pi eth0 receives an address from Jio by DHCP. Its MAC is {{ network.mac }}; current address: {{ network.uplink|join(', ') or 'not detected' }}. Reserve that MAC and current address on the Jio router if a fixed management address is needed.

Jio keeps DHCP for its own network. Pi-hole DHCP must be limited to the protected Wi‑Fi, never Jio LAN.

02 · PROTECTED HOTSPOT

Pi Wi‑Fi → home devices

Connect protected devices to PiGuard-Home. The Pi uses 10.78.0.1/24 on wlan0 and Pi-hole provides DHCP and DNS on that Wi‑Fi. The hotspot password is stored on the Pi at /var/lib/piguard-home-hotspot/wifi-key; view it locally with sudo cat.

Each device should receive a 10.78.0.100–199 address with gateway and DNS 10.78.0.1.

03 · VERIFY CLIENTS

Test every device type

Disable the client’s other Internet connections while testing. With Tor selected, confirm Tor Project’s check page ↗ reports Tor, and a Pi-hole blocked domain resolves to 0.0.0.0. Check that IPv6 has no direct default route.

Clients already on ordinary Jio Wi‑Fi are outside this protected network.

01 · WIRELESS UPLINK

Home or public Wi‑Fi → Pi wlan0

The Pi’s wlan0 uses DHCP on the upstream Wi‑Fi. Current MAC: {{ network.mac }}; address: {{ network.uplink|join(', ') or 'not detected' }}. Public networks may require a captive portal before Tor can connect.

02 · WIRED CLIENT

Pi Ethernet → laptop

Pi eth0 uses 10.78.0.1/24. Connect a laptop by cable with its own Wi‑Fi off. Pi-hole should assign 10.78.0.100–199, gateway 10.78.0.1, and DNS 10.78.0.1.

03 · VERIFY CLIENT

Check the laptop path

With Tor selected, verify the laptop reports Tor through Tor Project’s check page ↗ and Pi-hole blocks a controlled domain. Check that IPv6 has no direct default route.

04 · PRIVATE REMOTE ACCESS

Tailscale dashboard

Pi service: {{ 'active' if network.tailscale_active else 'not active' }}. Use the private Tailscale HTTPS address from authorized devices. Do not forward router ports or enable public Funnel.

05 · RECOVERY

Keep console access

If the home switch fails, the gateway remains blocked. At the Pi console, inspect sudo bash /home/krat0s/home_hotspot.sh status. To restore travel mode, unplug Ethernet first, then run sudo bash /home/krat0s/home_hotspot.sh restore.

Unsupported UDP and IPv6 client forwarding are blocked. Actual public Wi‑Fi still requires a location test.
